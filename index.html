2026 · Solo build · Thoughtworks / HDFC Life

AI UAT Support Agent

A human-in-the-loop agent that investigates UAT defects the way a senior engineer would.

The problem

Every UAT defect meant a developer rebuilding context by hand — the Jira thread, the QA screen recording, logs scattered across services, what was actually deployed when it broke — before writing a single line of fix. Slow, and expensive in AI tokens.

What it does

  • Pulls the Jira defect, comments and attachments, and reads the QA screen recording frame by frame.
  • Reads the real code and runs git blame / log before suspecting a line: is this old, stable code, or did something just change?
  • Queries Grafana Loki across services and follows a single request end-to-end.
  • Checks Helm history to see which commit of each service was live when the incident happened.
  • Builds a case, not a guess: every theory may only cite evidence it actually gathered.

Key decisions

One gate
It never edits code until a developer approves an approach.
Zero infrastructure
Runs inside the developer's own agent session. No backend, no hosted state.
Evidence-only reasoning

Clean hand-offs
Investigations live in a shared Git repo, so anyone can git pull and resume.

Thinker

Turns a sprawl of microservices into a queryable graph, then reasons over it to explain what a ticket will really touch.

The problem

In a multi-repo system, a ticket's real blast radius hides in the links between services — REST calls, Kafka topics, Spring events, WebSockets — none of which show up when you read one repo at a time.

My role

Co-came up with the idea; built the indexer and the multi-pass agent (draft → verify → adversarial).

Tap a node

RESTKafka

An LLM agent drafts the ticket analysis from the graph.

How it works

  1. Indextree-sitter parses every repo into File / Function / Endpoint / Topic nodes in a Kuzu graph.
  2. LinkResolves cross-repo REST, Kafka, Spring-event and WebSocket edges.
  3. DraftAn LLM agent drafts the ticket analysis from the graph.
  4. VerifyA second pass checks every claim against code citations.
  5. AttackAn adversarial pass tries to break the conclusion.
  6. ViewA 3D system graph with analysis and source side by side.
